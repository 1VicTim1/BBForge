# BBForge

[![CI](https://github.com/1VicTim1/BBForge/actions/workflows/ci.yml/badge.svg)](https://github.com/1VicTim1/BBForge/actions/workflows/ci.yml)
[![Version](https://img.shields.io/badge/version-0.1.0-8b7cf6)](https://github.com/1VicTim1/BBForge/releases/tag/v0.1.0)
[![License: MIT](https://img.shields.io/badge/license-MIT-6f7682)](LICENSE)

BBForge — настольный редактор и визуальный конструктор BBCode-постов и шапок 4PDA для Linux и Windows. Исходный BBCode остаётся главным документом: действия в конструкторе применяют точечные изменения и используют общую с редактором историю Undo/Redo.

## Возможности первой версии

- CodeMirror 6: подсветка BBCode, поиск, undo/redo и сворачивание spoiler.
- Lossless-парсер и линтер на Rust.
- Дерево тегов, переход к исходному диапазону и список диагностик.
- Локальный React-предпросмотр без исполнения HTML и загрузки изображений.
- Открытие и атомарное сохранение UTF-8 с сохранением BOM и смешанных LF/CRLF.
- Проверка неизвестных тегов, параметров, пересечений, незакрытых тегов и повторных ссылок.
- Тёмное рабочее пространство в духе IDE: режимы «Код / Конструктор / Рядом», регулируемые панели, сохраняемая раскладка, строка состояния.
- Визуальное редактирование текста, оформление, цвет текста и фона, ссылки, списки, цитаты и код.
- Создание спойлера вокруг выделения, переименование, перетаскивание в дереве (до / внутрь / после), перемещение кнопками, извлечение из родителя и удаление оболочки.
- Alt+Enter и кнопки в панели проблем открывают исправления с diff. Документ изменяется только после применения.
- Несколько файлов открываются во вкладках. Для каждой вкладки сохраняются свой курсор, выделение и история Undo/Redo.
- Рабочий сеанс восстанавливает вкладки, их порядок, активный документ и несохранённый текст после перезапуска. Восстановленный текст начинает новую историю Undo.
- Перед сохранением BBForge сверяет отпечаток файла и не перезаписывает изменения, внесённые другой программой.
- Системное контекстное меню заменено меню BBForge с отдельными командами для кода, конструктора, предпросмотра, ссылок, медиа и полей ввода.

В конструкторе выберите текст для оформления; щелчок по блоку открывает его свойства снизу. Для пустого спойлера есть редактируемая строка. Неизвестные и повреждённые теги показываются отдельными блоками с переходом в код. Вставка с BBCode-тегами предлагает выбрать интерпретацию; при вставке буквального текста используется оболочка `code`.

Перед структурной операцией дождитесь надписи «Синхронизирован с кодом». Незавершённая IME-композиция блокирует смену режима и файловые действия. Вложенные спойлеры глубже второго уровня изначально свёрнуты; содержимое вне экрана монтируется по мере прокрутки. Текстовый блок больше 64 КиБ редактируется в коде.

Предпросмотр ориентирован на синтаксис 4PDA, но не гарантирует пиксельное совпадение с форумным движком. Ссылки открываются только после клика и только для `http`, `https` и `mailto`.

В предпросмотре выделенный фрагмент можно скопировать как видимый текст, BBCode без частично выделенных внешних оболочек или BBCode с минимальной сбалансированной цепочкой внешнего оформления. Команда «К исходнику» в предпросмотре и конструкторе открывает точный диапазон в редакторе.

Снимок сеанса хранится в каталоге данных приложения как `workspace-v1.json`; рядом сохраняется последняя валидная резервная копия. Лимит одного восстановленного документа — 32 МиБ, всего сеанса — 128 МиБ. Если восстановление мешает запуску, закройте BBForge и удалите `workspace-v1.json` и `workspace-v1.json.bak` из каталога данных приложения. Исходные файлы при этом не удаляются.

## Разработка

Требуются Node.js 24 и актуальный стабильный Rust.

```bash
npm ci
npm run dev
```

Браузерный dev-режим показывает интерфейс, но Rust-анализ и файловые диалоги работают в Tauri:

```bash
npm run tauri:dev
```

Для Linux нужны WebKitGTK 4.1, GTK 3 и стандартные зависимости Tauri. На Ubuntu:

```bash
sudo apt install libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf
```

## Сборка

```bash
npm run tauri:build
```

Результаты появляются в `target/release/bundle`. Windows использует системный WebView2 Runtime; современные Windows 10/11 обычно уже содержат его. Linux-пакеты зависят от системного WebKitGTK.

В dev-режиме используется фича `desktop-runtime`: окно загружает Vite-сервер, правки интерфейса применяются сразу, а изменения Rust пересобираются автоматически. `desktop` дополнительно включает `tauri/custom-protocol`: готовое приложение загружает встроенные ресурсы и не требует Vite или Node.js. Основная сборка использует нативный WebKitGTK 4.1; совместимость с конкретной версией RED OS или CachyOS требует проверки на ней. Экспериментальный `legacy-webkit` отключён по умолчанию: его заглушки API не являются гарантией полноценной работы старого WebKitGTK.

Проверка настоящего Linux release-окна без dev-сервера (WebKitWebDriver, Xvfb и D-Bus):

```bash
BBFORGE_BINARY="$PWD/target/release/bbforge-app" bash scripts/smoke-desktop.sh
```

Проверка использует настоящий Rust IPC, меняет текст в конструкторе и проверяет изменение кода. Отчёт и снимок окна записываются в `artifacts/native-smoke.json` и `artifacts/bbforge-native-smoke.png`. WebDriver-автоматизация и отключение sandbox предназначены только для тестового контейнера; обычный запуск не требует этих переменных.
